## 1. 验证目标

## 4. 关键发现（直接影响正式实现）

### 4.1 进度输出是「退格覆盖式」，不能按行取第一个百分比
`7zz` 在管道（非 TTY）下的原始输出形如：

```
  0%\b\b\b\b    \b\b\b\b 32%\b\b\b\b    \b\b\b\b 63%\b\b\b\b    \b\b\b\b 93%\b\b\b\b
```

- 整行只有一个换行，中间用 `\b` 回退覆盖；
- 必须**提取该块内所有 `NN%`**，按顺序上报，否则只会拿到 0%；
- 本次修正后压缩进度从 `max=0` 变为 `max=87`。

### 4.2 7-Zip 不保证输出 100%
收尾阶段可能停在 87%/93%，成功退出时 UI 应**主动补到 100%**，避免用户看到「卡在 87% 却已完成」。

### 4.3 取消行为可接受
`Process.terminate()`（SIGTERM）即可让 `7zz` 停止，退出码 255。正式实现需在取消后：
- 等待进程退出（避免孤儿）；
- 清理暂存区；
- 保留原归档不动。

### 4.4 路径校验必须在解压前做
`7zz` 本身不应被当作安全边界。正确做法：先 `l -slt -ba` 拿条目清单 → 逐条校验 → 再解压。本次 5 条恶意样本拦截 4 条（`safe.txt` 正常放行）。

### 4.5 CLT-only 环境无法构建完整 .app
- `swift build` 的 manifest 链接在仅装 CLT 的机器上失败（`PackageDescription.Package` 未定义符号）；
- 本次改用 `swiftc` 直接编译源码，验证逻辑不受影响；
- **正式开发必须安装完整 Xcode**（SwiftUI、FinderSync、签名、公证都依赖 Xcode）。

## 6. 结论与下一步

**结论：技术路线成立。** `7zz` 子进程方案在 macOS 上可稳定完成压缩、解压、列表、进度、取消与路径校验，足以支撑 v1.0 的「打开 / 浏览 / 解压 / 压缩」闭环。

**下一步（M1 前置）**：
1. 安装完整 Xcode，创建 SwiftUI 空壳 App（macOS 14+，Universal 2）；
2. 把 `SevenZipRunner` / `ArchiveLister` / `PathValidator` 迁入 `Core` 模块并补单测；
3. 用 Xcode 建 FinderSync 扩展 target，验证右键单项菜单 + URL Scheme 唤起；
4. 给内置 `7zz` 单独签名，跑一次公证冒烟（正式发布前）。

**未覆盖项（诚实标注）**：
- Intel（x86_64）实机未测（本机为 arm64；二进制本身是 Universal 2）；
- FinderSync / QuickLook 扩展未在 M0 验证（依赖完整 Xcode）；
- 大包（>10GB）与超多文件（>10 万）性能未压测；
- 加密/分卷未验证（v1.2 范围）。
