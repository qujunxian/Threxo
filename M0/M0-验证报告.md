# M0 技术验证报告 — 7zz 能不能用

项目：macOS 解压缩工具（当时内部代号 MacZip，产品名还没定）
日期：2026-10-30，结论：7 项检查全部通过
做法：用 Swift 命令行工程直接调官方 7-Zip `7zz`，覆盖压缩、解压、列表、进度、取消、路径安全

## 1. 想先搞清楚什么

动手写 SwiftUI 界面之前，有四件事没底，得先证一遍：

1. 官方 `7zz` 能不能在 macOS 上被进程稳定调用；
2. 能不能把归档列表解析回文件树；
3. 压缩解压能不能拿到实时进度，能不能中途取消；
4. 解压前能不能认出 `../` 这类恶意条目。

## 2. 环境

| 项 | 值 |
|---|---|
| 系统 | macOS 27.0.1（arm64） |
| 编译器 | Apple Swift 6.3.3（Command Line Tools） |
| Xcode | 没装完整版，只有 CLT，`xcodebuild` 用不了 |
| 引擎 | 7-Zip `7zz` 26.04，Universal 2（x86_64 + arm64） |
| 引擎来源 | 7-zip.org 官方发布的二进制，量产时由本项目自己签 |

## 3. 七项检查

| # | 检查项 | 结果 | 细节 |
|---|---|---|---|
| 1 | `7zz` 能跑、能输出版本 | 通过 | `7-Zip (z) 26.04 (arm64)`，exit 0 |
| 2 | 压 ZIP | 通过 | 32MB 样本压成 `sample.zip`，exit 0 |
| 3 | 压缩进度 | 通过 | 收到 7 个进度事件，最高 87% |

7 项通过，0 项失败，0 项跳过。

## 4. 几个直接影响实现的发现

### 4.1 进度是退格覆盖输出，不能按行取第一个百分比

`7zz` 在管道（非 TTY）下的原始输出长这样：

```
  0%\b\b\b\b    \b\b\b\b 32%\b\b\b\b    \b\b\b\b 63%\b\b\b\b    \b\b\b\b 93%\b\b\b\b
```

整行只有一个换行，中间靠 `\b` 回退覆盖。得把这一块里的所有 `NN%` 都提出来按顺序上报，只取第一个的话永远是 0%。改完以后压缩进度的最大值从 0 变成 87。

### 4.2 7-Zip 不保证输出 100%

收尾可能停在 87%、93%，成功退出时界面得自己补到 100%，不然用户会看到「卡在 87% 但已经完成了」。

### 4.3 取消的行为可以接受

`Process.terminate()` 发 SIGTERM，`7zz` 就停了，退出码 255。正式实现里取消后还要做三件事：等进程真的退出（别留孤儿）、清掉暂存区、原归档不动。

### 4.4 路径校验一定要在解压前做

不能把 `7zz` 当安全边界。正确顺序是先 `l -slt -ba` 拿清单，逐条校验，再解压。这次 5 条恶意样本拦住 4 条，正常文件放行。

### 4.5 只有 CLT 的环境建不出完整 .app

`swift build` 的 manifest 在只装 CLT 的机器上链接失败（`PackageDescription.Package` 未定义符号）。这次改用 `swiftc` 直接编源码，逻辑验证不受影响。正式开发必须装完整 Xcode，SwiftUI、FinderSync、签名、公证都靠它。

## 5. 产物

```
M0/
├─ Package.swift                     # SwiftPM 清单（本机 CLT 下不可用，留给 Xcode 环境）
├─ Sources/m0verify/
│  ├─ SevenZipRunner.swift           # Process 封装 + 进度解析 + 取消
│  ├─ ArchiveLister.swift            # l -slt -ba 解析 → 条目模型
│  ├─ PathValidator.swift            # 路径穿越/绝对路径校验

└─ m0verify                          # 编译产物（arm64，可直接运行）
```

怎么跑：

```bash
cd M0
./m0verify --7zz bin/7zz
```

## 6. 结论

技术路线是通的。`7zz` 子进程方案在 macOS 上能稳定完成压缩、解压、列表、进度、取消和路径校验，够撑起 v1.0 的「打开 / 浏览 / 解压 / 压缩」。

接下来（进 M1 之前）：

1. 装完整 Xcode，建 SwiftUI 空壳 App（macOS 14+，Universal 2）；
2. 把 `SevenZipRunner` / `ArchiveLister` / `PathValidator` 挪进 `Core` 模块，补单测；
3. 用 Xcode 建 FinderSync 扩展 target，验证右键单项菜单和 URL Scheme 唤起；
4. 给内置 `7zz` 单独签名，跑一次公证冒烟。

这次没覆盖的：

- Intel（x86_64）实机没测，本机是 arm64，二进制本身是 Universal 2；
- FinderSync / QuickLook 扩展没验，依赖完整 Xcode；
- 大包（>10GB）和超多文件（>10 万）没压测；
- 加密和分卷没验，那是后面版本的事。
